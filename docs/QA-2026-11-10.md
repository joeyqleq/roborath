# RoboRath independent QA record — 2026-11-10

## Scope and safety

This is an offline regression record for the updated Astra handoff and its
2026-11-10 addendum. It covers parser boundaries, immutable-ID authorization,
tool/reasoning artifact containment, UTF-8 chat limits, and then the integrated
stream archive, retention and scheduled-message work as those APIs land.
Tests use in-memory SQLite and deterministic fixtures. They do not call an
inference provider, Twitch, Mattermost, or a production host; they do not print
or load production credentials.

`tests/test_adversarial_qa.py` generates at least 470 deterministic cases per
run: 120 tool-artifact wrapper combinations, 150 Unicode output samples, 100
non-invocations, 100 forged administrator attempts (with two protected
operations per attempt), identity/configuration and unlimited-role cases, plus
an end-to-end IRC-frame byte-budget check. This is boundary and state-machine
coverage, not a claim that 470 live model responses were evaluated.

## Findings from the independent source audit

At the initial audit of baseline `e610c28`:

- `formatting.humanize` converted ordinary JSON but passed through `<think>` and
  tool-call markup. No public-output guard prevented tool argument JSON from
  looking like an answer. This is a critical output-boundary regression case.
- `TestAccess.allowed` granted the owner capability while the database mute flag
  was set. Outbound checks in the transport are a separate guard; callers of
  this method should not mistake it for permission to send while muted.
- Public specialist invocation was intentionally strict about command prefixes.
  Existing help supported only two pages; help/parser consistency needs direct
  tests once the revised help contract is integrated.
- Existing tests covered basic quota scoping, ID spoofing, outbound mute/revoke,
  and UTF-8 clipping. They did not exercise stream-wide cross-viewer recall,
  derived-index retention, reminder tick deduplication, reconnects, or leaked
  tool-call representations.

The earlier baseline run was interrupted during dependency installation and did
not produce a test result. Do not treat that attempt as verification.

## Evaluation limits

Deterministic unit tests can establish parser behavior, data isolation, output
byte limits, timer deduplication, retention and authorization properties. They
cannot establish that a language model is funny, consistently in character,
historically nuanced about Mao, non-repetitive, or reliably sourced. Those
properties require an authorized, redacted, scored provider bake-off. No live
Twitch posting or public QA grant is part of this evaluation.

## Final integrated run

The full offline suite passed on both fresh virtual environments after module
integration:

- CPython 3.14 environment `/tmp/roborath-astra-venv`: `PYTHONPATH=src/roborath
  /tmp/roborath-astra-venv/bin/python -m unittest discover -s tests -p
  'test_*.py' -v` — 158 tests passed.
- CPython 3.13 environment `/tmp/roborath-astra-313`: same command with the
  corresponding interpreter — 158 tests passed.
- The repository's extra bridge and IRC regression scripts also run in the
  CI workflow after the full suite. In an independent direct invocation,
  `tests/test_bridge.py` passed, but `tests/test_irc_adapter.py` failed at line
  40: it attempted to grant a fixture using owner ID `1414798445` without
  setting `ROBORATH_OWNER_TWITCH_USER_ID` in that standalone process. It had
  passed during unittest discovery because environment state was initialized by
  other tests. This order-dependent CI check needs a self-contained environment
  fixture before the extra-script result can be called green. Setting
  `ROBORATH_OWNER_TWITCH_USER_ID=1414798445` explicitly made the script pass,
  which confirms the cause without changing the CI command's actual outcome.

The suite uses mock provider responses for relay/model tests. It validates
request correlation, source URL syntax, assistant-final response shape, tool
artifact rejection, evidence presence and budget reservations. It does not
confirm that a syntactically cited URL supports a claim or that the current ORA1
specialist can return a fresh, accurate answer. No production endpoint was
called. Those end-to-end checks remain unverified.

Two supporting observations from the final audit:

- Actual-wire tests include the verified `@login` prefix and Unicode and pass
  the 420-byte cap after transport clipping. The earlier 429-byte failure was
  resolved in the integrated transport change.
- The router ledger keeps absent provider token counts nullable, while its
  in-memory `Response` uses estimates as fallback counts for routing results.
  Any operator report must label those fallback values as estimates. Mattermost
  relay cost remains a conservative reserved amount because its plugin does not
  report provider token usage in the inspected response contract.

These are offline results only. Model humor, political satire, historical
nuance, and consistent character still need a separately authorized, redacted
provider bake-off; public Twitch posting and public QA grants were not tested.

## Owner persona and context regressions

`tests/test_qa_final.py` adds synthetic cases for the owner's requested
Chairman/Boss/Captain/Leader/Comandante role, loyal servant framing, respectful
tone toward the owner, permission for profanity and dirty humor, an explicit
"wait for banana" signal, a later unrelated factual question, and a sourced
search follow-up. It checks the actual mocked router system message for a
verified owner ID, then verifies that a display-name match on another ID does
not receive the owner voice. A separate SQLite test verifies that the owner
wake phrase survives store reconstruction, is matched exactly, and cannot be
triggered by another numeric user. No private transcript lines are stored.

All five tests passed on CPython 3.14 with the mocked provider. They verify that
the owner voice is injected only on the canonical numeric owner route; they do
not prove a live model consistently follows the requested tone. The history
tests verify what the model receives, not the generated answer quality.
